# ADR-0001：移除目录累积池与手动重扫

- 状态：已采纳（2026-11-08）

## 背景
早期无法一次性拿到“全部提示词段/工具”，于是用“目录累积池（catalog_*）+ 手动重扫”来凑全量：
每次装配把见到的段/工具并入池子，重扫时整体替换。池子只增不减，且是**跨预设全局**的。

## 问题
- 全局池会把**别的预设独有**的段/工具串进当前预设（如 `tools:ptc-only` 串到一般预设）。
- 池子里的历史条目可能早已不存在，需要手动重扫清理。
- 清单/预览不再等于该预设的真实装配（“有就有”退化为“见过就有”）。

## 决策
- 删除“目录累积池 + 手动重扫”。清单只来自**当前预设真实装配**（动态枚举），有就有、没有就没有；
  首次运行/插件后注册的段同样通过真实装配枚举得到。

## 后果
- 好处：预设天然隔离；清单与模型输入一致；无需手动维护。
- 代价：不再保留“跨预设历史条目”这种能力（本就是权宜）。
- 彻底移除：DB 迁移 `DROP TABLE IF EXISTS catalog_section / catalog_tool`；备份/恢复不再含 catalog 字段；
  删除 `catalog.js` 及其测试（单用户，无兼容补丁）。

## 备选
- 给池子加“预设归属”过滤：仍保留全局池复杂度，且运行时归属不可靠 → 弃用。
