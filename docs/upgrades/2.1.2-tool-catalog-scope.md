# 2.1.2 — 工具目录与真实会话同源

版本 2.1.2，宿主契约不变（`engines.dsh: ^0.2.2-rc.1`）。本次修两个由**实读宿主源码**定位的可观测缺陷，不再靠名字猜。

## 缺陷 1：右栏只显示 38 个工具（真实注入 50）

2.1.0/2.1.1 的 `/preview` 把**提示词段**改成了同预设活动 agent 的真实装配（`ADR-0005 D3`），但**工具目录**仍取 `assembled.tools`——`assembled = ctx.systemPrompt.assemble(hint)`，`hint.scope = presetScopeKey`（预设 scope key）。

宿主源码证据：
- `packages/core/agent/src/dispatch.ts:174-175`：`assembleContextFor(agent, signal)` 返回 `{ agent, scope: agent }`——**真实会话装配的 scope 是 live Agent 对象自身，不是 preset scope key**。
- `packages/core/agent-loop/src/agent.ts:292-294`：`toolSet = await ctx.tools.resolve({agent, modelSelection, signal})`，`assembly = await ctx.systemPrompt.assemble({ ...assembleContextFor(this, signal), modelSelection: selection, toolSet })`。
- `assembly.tools` → `buildRequest(...)` → `GenerateOptions.tools`（`agent.ts:479`、`:656`、`:731-736`；`docs/subsystems/llm-streaming.md:678/722`）。
- `packages/core/system-prompt/src/index.ts:621` `const scope = context.scope`；`:640-644` providers = global + `scopeLayers`（`chainLayers(scope)`）；`:674` `orderTools(...)`；`:687` `return { ...transformed, tools }`。**scope 决定 provider 集合**，所以 agent scope 的可见集 ⊇ preset scope。

`ctx.tools.schemas(agent)`（`packages/core/tools/src/index.ts:305-317`）返回该 agent 的注册视图全集（global + 祖先/preset + agent own，shadow 与 restrictions 已生效），**不带 toolSet 时含条件注册工具**，是「不区分 step 的可见工具目录」的正确入口（`docs/subsystems/tools.md:695/708`）；`schemas(undefined)` 只是 global view，不能用来代表会话。

⚠️ 不能用 `assemble({scope: agent}).tools` 当主源：PTC 模式下 executor 的 `describe()` 忽略传入定义、只返回 `run_code`（`packages/core/tools/src/tool-executor-ptc/src/index.ts:47-49`），会塌缩；`ctx.tools.schemas(agent)` 不经 executor，不受影响。插件也拿不到 `modelSelection`/`signal`，无法调 `resolve()` 复刻 step 准入，故用不带 toolSet 的注册视图（与 `/session` 的 `visibleTools` 同源）。

**改动**：`buildPreview` 新增 `visibleFinalTools`，主源 `toolSchemasOf(ctx, livePromptAgent, true)`，回落 `previewSource.tools` / `finalTools`；右栏 `tools`、`registryTools`、`registryTotal` 全部改用这份。`finalTools`（预设装配）仍保留给 `buildToolUnion` 的 `extraTools` 与排序，遮蔽池结构不变。无活动 agent 时回落纯预设装配。

## 缺陷 2：`apply_patch` 不出现在只读池

用户前提「插件遮蔽了原生 `apply_patch`」不成立，根因在宿主配置：

- `packages/fs/tool-fs/src/index.ts:53` `applyPatch: z.boolean().default(false)`；`:101` `if (resolved.applyPatch) applyApplyPatchTool(ctx, sandbox)`——**只有 true 才注册原生定义**。
- 出厂组合行 `packages/bundle/web-app/presets/standard.patch.yml:27-31`（以及 `ptc/cordis`、`bundle/base/cordis.patch.yml:300`）全是 **`applyPatch: false`**；运行时 `~/.dsh/profiles/web/cordis.patch.yml` 三处 tool-fs 行同样 false。`packages/bundle/web-app/cordis.patch.yml:517-518` 把 host 的 tool-fs 行 `disabled: true`，工具由 preset 层重挂。
- `docs/tool-catalog.md:33/1178` 与 `docs/upgrade-guide/v0.2.2-alpha.2/fs-observation-policy-default-off/guide.md:14` 声称 Web standard `applyPatch: true`，**与实际产物矛盾**（该目录自己也注明「the catalog sets it so the schema is documented」）。以实装 YAML/运行时 profile 为准。
- `dsh-hashline-edit@0.2.0` 的 `dsh/index.ts` 明确只把 `read` 当遮蔽对象（「shadow the preset's built-in `read`」）；`apply_patch` 由 `registerApplyPatchTool` 在 agent 作用域**首次注册**，`cordis.patch.yml` 不覆盖 tool-fs 行。

⇒ 继承层（global/preset）**不存在**名为 `apply_patch` 的原生定义；插件注册的是**纯新增**（`agentOnly → locked-agent`），不是同名遮蔽，没有「被顶掉的原定义」可取（`definitions(presetScopeKey)` 里也没有，teammate 实读 `agent-preset-registry` 确认 `lease.key` 与 tool-fs 注册 scope 是同一个）。2.1.1 的「不凭空造行」口径因此不显示它——语义上正确，但用户无法在只读池看到这个被插件接管的工具。

**改动（口径）**：客户端 `buildMaskedPool` 纳入 `locked-agent`，把这类工具在「完整目录 / 已遮蔽（只读）」里按**「会话级」**如实列出（徽标「会话级」而非「同名遮蔽」，不伪造遮蔽）。`completeCatalogHint` 本来就宣称该池包含「agent 作用域注册」，这次让实现与文案一致。同时修正 `toolAgentScopedHint` 的误导文案：这些工具**可以**按阶段隐藏（`isToggleable` 含 `locked-agent`，靠装配后过滤 `tools` 实现），不是「只能查看」。

`read` 这类**真·同名遮蔽**仍是 `masked-shadow`（继承层有 `read` 原定义），与纯新增区分；`test/tool-catalog-scope.test.mjs` ⑤ 钉住这条边界。

## 明确不纳入

- 不改 `buildToolUnion` 的判定、`tools.restrict` / 阶段过滤 / `tools/pre-execute`、`editPresetId` 与 live 提示词视图；不接管工具 schema 的 `description`；不新增 ADR（探测/数据源修正记在升级记录即可）。
- 不按 `docs/tool-catalog.md` 的静态描述硬编码工具列表——宿主配置可覆盖，以运行时 `schemas(agent)` 为准。

## 影响模块

- `vendor/prompt-customizer/index.js`：`buildPreview` 的 `visibleFinalTools` / `registryTools` / `registryTotal` / `tools` 字段与注释。
- `src/client/prompt/`：`tool-pool.ts`（`buildMaskedPool` 纳入 `locked-agent`）、`ToolsPane.tsx`（`stateBadge` 四态）、`locales.ts`（`toolAgentScopedHint` 中英、`completeCatalogHint` 不变）。
- 测试：反转 5 个旧断言（`rc2-preview` / `session-preview` / `tool-mask-pool` / `universal-prompt-takeover`），新增 `test/tool-catalog-scope.test.mjs`（5 用例）。

## 验证与反例

- 本机 `npm run check`：全量单测 **175/175 通过**、构建产物重建、宿主 / 客户端 smoke 全绿。
- **反例实测**：把主源 `toolSchemasOf(ctx, livePromptAgent, true)` 换回 `toolSchemasOf(ctx, scopeKey, true)`（presetScopeKey），`test/tool-catalog-scope.test.mjs` 的 **①③④ 全红、②⑤ 仍绿**；还原后 175/175。
- 覆盖：① 右栏 = agent scope 注册视图（含 `apply_patch`/`undo_last_edit`）；② 无 live agent 回落纯预设；③ 与 `/session` 同源；④ PTC 塌缩防护（`assemble().tools` 只剩 `run_code` 时仍用 `schemas(agent)`）；⑤ 纯新增不伪造 `masked-shadow`、`read` 仍是真同名遮蔽。

## 附：文档与产物矛盾（供后续排查）

`docs/tool-catalog.md` 与 `v0.2.2-alpha.2` 升级指南称 Web standard 启用 `applyPatch: true`，但 `0.2.2-rc.1` 的 shipped YAML 与运行时 profile 全是 `false`。若用户在 Agent presets 设置页或 `standard.patch.yml` 把它改成 `true`，继承层就会注册原生 `apply_patch`，插件的注册变为真同名遮蔽（`masked-shadow`）——这与本版逻辑兼容，届时遮蔽池会出现「同名遮蔽」行而不是「会话级」行。
