# 2.1.1 — 同名遮蔽探测

版本 2.1.1，宿主契约不变（`engines.dsh: ^0.2.2-rc.1`）。本次只改**工具遮蔽池的探测**，不改 2.1.0 的提示词接管链路（ADR-0005 D6 保持）。

## 缺陷（2.1.0 现状）

`buildToolUnion` 用单点判定识别同名遮蔽：

```js
const shadowed = hasLive && inPreset && inLive && presetDefs !== null && liveDefs !== null
  && presetDefs.get(name) !== liveDefs.get(name)
```

它会把以下场景漏掉，导致被插件同名工具顶掉的原生工具不进只读遮蔽池：

1. **`ctx.tools.definitions` 缺席 / 抛错 / 返回的数组里没有该 name**：`presetDefs`/`liveDefs` 为 `null` 或 `get(name)` 为 `undefined`，源码注释也承认「没有 definitions 时无法判定，退化为同名即同一工具」。
2. **`inPreset = false`**：宿主 `apply_patch` 是条件注册（`applyPatch: true` 才挂）；当前 profile 没挂载原生 `apply_patch` 时，插件 agent 作用域注册的那一份被判成 `agentOnly → locked-agent`（启用列表），不是遮蔽。
3. **0.2.1 的 `tools.restrict`**：宿主契约 `ToolRestriction` 只作用于继承层，「scope's OWN registrations stay exempt」（`docs/subsystems/tools.md:165`）；插件自己的 `apply_patch` 仍在 agent 视图 → `inLive=true` → `restricted` 不成立，只能靠 `shadowed`，而 `shadowed` 有 1/2 的退化。
4. **来源标错**：`emit` 的 `masked-plugin` 行 source 走 `sourceForTool(..., role:'agent')`，同名遮蔽时被判成 `agentSourceOf(agent)` → 被顶掉的明明是继承层原生工具，却落到「会话」分组。

## 决策

- **多证据判定**（`buildToolUnion`）：只要继承层（global ∪ preset）查得到同名定义 / schema，且 agent 视图里的同名工具与它「不是同一注册」，就判同名遮蔽。证据三条取一：① `definitions` 引用不同（精确，保留）；② `definitions` 缺席/缺项时 `description` 不同（宿主 `schemas()` 只暴露 name/description/parameters）；③ 只有继承层定义、agent 层另有注册（`inPreset=false`）。**继承层查不到同名定义时绝不误判**——纯 agent 新增（如 `undo_last_edit`）仍是 `locked-agent`。
- **新状态 `masked-shadow`**（区别于 `masked-plugin` = 被别的插件 restrict）：`source` 用 `sourceOverride` 标继承层（`global` / `preset:<id>`），`description` 取被顶掉的原定义，`shadowedBy = { name, source: agentSourceOf(liveAgent) }` 指向顶掉它的插件工具，`keySuffix = 'shadowed'` 保证与 `locked-agent` 行的 `entryKey` 不冲突。
- **客户端**：`ToolState` / `toolStateOf` / `buildMaskedPool` 纳入 `masked-shadow`；徽标「同名遮蔽」与提示说明「只读、不能反开」；分组按继承层 source 落到「预设 / 全局」而不是「会话」。
- **口径（推荐）**：继承层查不到同名定义时**不凭空造行**，插件工具只显示「会话级」的 `locked-agent` 行。0.2.0 的 `apply_patch` 在没挂载原生 `apply_patch` 的 profile 上仍不会出现在遮蔽池——这是诚实的语义，不是缺陷。

## 行为变化（用户可见）

- 同名遮蔽（如 0.2.0 hashline 的 `read`、0.2.1 的 `apply_patch`）在 `definitions` 退化、profile 未挂载原生、restrict 场景下都会出现在「完整目录 / 已遮蔽（只读）」，徽标「同名遮蔽」，来源落在正确的继承层分组，并带 `shadowedBy`。
- `masked-plugin`（被别的插件 restrict）、`masked-own`（本插件 MCP 遮蔽）、工具目录可开关项与阶段过滤全部不变。

## 明确不纳入

- 不改 `finalTools` / 工具目录数据源（ADR-0005 D6）、不改 `tools.restrict` / 阶段过滤 / `tools/pre-execute`、不改 `buildPreview` 的 `editPresetId` 与 live 提示词视图；不接管工具 schema 的 `description`。
- 不新增 ADR：本次是探测逻辑增强，决策与边界记在本升级记录即可（ADR-0005 仍是提示词接管的唯一决策文档）。

## 影响模块

- `vendor/prompt-customizer/index.js`：`buildToolUnion`（判定 / `emit` 第 6 参 `shadowedBy` / `rankOf`）、`catalogTools` 保留条件、`buildInventory` 透传 `maskedByShadow` / `shadowedBy`。
- `src/client/prompt/`：`types.ts`（`ToolState` / `BaseTool` / `Inventory.tools`）、`tool-pool.ts`、`locales.ts`（中英徽标与提示）、`ToolsPane.tsx`（`stateBadge`）。
- 测试：`test/tool-shadow.test.mjs` 断言改为 `masked-shadow`；新增 `test/tool-shadow-universal.test.mjs`（6 组 / 8 场景）。

## 验证与反例

- 本机 `npm run check`：全量单测 **170/170 通过**、构建产物重建、宿主 / 客户端 smoke 全绿。
- 反例：把判定换回单点 `presetDefs.get(name) !== liveDefs.get(name)`，`test/tool-shadow-universal.test.mjs` 的 ①②③ 必须失败；为 `read` 写死特判，用例 ⑤（换名字）必须失败。
- 组合用例：① `definitions` 缺席；② agent `definitions` 缺该 name；③ `schemas` 未挂载原生但 `definitions` 有（`inPreset=false`）；④ 0.2.1 restrict 场景；⑤ 任意工具名（`apply_patch` / `edit` / `plugin:custom`）；⑥ 不误判 agent 新增 / 同一注册不拆行 / 跨预设不串台 / 无活动 agent 不抛错 / 工具目录状态不变。
