# 提示词 / 工具 / 上下文 控制模型 — 设计共识

> 状态：设计共识（实现前）。日期：2026-11-08。术语见根目录 `GLOSSARY.md`。
> 兼容性：**允许破坏式更新，不保留前向兼容**（见 ADR-0003）。

## 1. 背景与问题

面板现能定制“预设级/工作区级”的提示词段与工具显隐，但存在若干问题：

1. **禁用技能卡片信息丢失**：被“全局/预设/工作区”禁用的技能，在面板里显示成桩信息
   （`disabled by dsh-prompt-customizer for preset "..."`、`0 文件`），而不是原有内容。
2. **提示词预览混入工具格式**：右侧“提示词预览”把工具声明/schema/签名也渲染进去。
3. **跨预设串台（未彻底）**：一般预设里仍能出现 ptc 专属的**系统提示词段**（列表与正文都有），
   但实际并未注入模型——说明预览/清单不是该预设的“真实装配”。
4. **同名不同源工具无法区分**：某个插件遮蔽了原生 `apply_patch` 并注册同名工具后，面板把它们
   当成同一个；期望“遮蔽池显示原生、启用列表显示插件自带”。
5. **重复的权宜设计**：历史上用“目录累积池 + 手动重扫”来凑齐全量，现已可从真实装配动态枚举，
   该设计应删除（已在 1.1.3 移除，本设计确认其为正式方向）。

## 2. 目标 / 非目标

**目标**
- 面板对“系统提示词段（含并入系统提示词的 host contexts）”与“工具”的展示与控制，严格反映
  **当前预设（叠加工作区）的真实装配**：有就有、没有就没有，不多不少。
- 禁用技能卡片与启用时**信息完全一致**，仅状态为“已停用”。
- 同名不同源的段/工具按“名字+来源”分别展示与控制。
- 动态枚举：首次运行/插件后注册的段，出现即可控，无需手动重扫。

**非目标**
- 不接管“不并入系统提示词”的真正运行时上下文（会话消息、工具结果等）。
- 不提供工具签名/schema 的编辑（只能控工具显隐）。
- 不做“按固定名单匹配段”的实现（不硬编码段名）。

## 3. 决策（Decisions）

- **D1 真实装配预览**：所有级别的“提示词预览”= 该预设（+工作区）实际发给模型的**系统提示词**，
  只含系统提示词段，不含工具声明/schema/签名。无活动会话时，跑一次该预设的真实装配作为预览。
- **D2 预览只渲染 sections**：工具描述属提示词内容（作为系统提示词段呈现）；工具签名/声明不进预览。
- **D3 严格预设隔离**：清单与预览只来自该预设真实装配，禁止并集/跨预设混入（修复 ptc 段串台）。
- **D4 动态枚举、不按名字匹配**：从真实装配动态枚举所有段（含首次运行注册/插件注册），基于实际结果，
  不依赖固定名单。
- **D5 身份 = 名字 + 来源**：段与工具的隐藏/显隐以“名字+来源”为标识；同名不同源区分对待。
- **D6 工具页 vs 提示词页职责独立**：工具页只控“工具是否可用”；提示词页只控“段（含工具描述文本）”
  显隐。禁用工具不自动隐藏其描述段。
- **D7 运行时上下文（并入系统提示词的部分）可显隐**：允许拦截 host `contexts` 中并入系统提示词的部分；
  真正 user-role 上下文不管。范围与提示词段一致：预设级+工作区级、三阶段独立、受“三态同步”。
- **D8 技能禁用卡片全量还原**：描述/文件数/路径/正文与启用时一致，仅状态为“已停用”。
- **D9 旧隐藏名单忽略**：改为“名字+来源”后，旧配置中只有名字的隐藏名单不迁移、忽略。
- **D10 移除目录池/重扫**：不再累积、不再手动重扫；清单只来自真实装配。并**彻底移除** `catalog_*` 表与
  备份/恢复中的 catalog 字段（无兼容补丁）。

## 4. 行为规格

### 4.1 技能卡片（SKILL）
- 启用与禁用卡片除“开关/已停用”外，描述、文件数、路径/来源、可查看正文等**完全一致**。
- 禁用仅表示“模型侧不可用 + 开关为关”，不影响面板展示的真实元数据。

### 4.2 提示词页（段）
- 左栏：动态枚举当前预设真实装配里的系统提示词段（含并入系统提示词的 contexts），每条带来源标签、
  可勾选显隐；同名不同源分列。
- 右栏：该预设真实系统提示词正文（仅 sections，不含工具 schema/签名）。
- 首次运行/插件后注册的段：出现即可控（动态枚举，无需重扫）。

### 4.3 工具页
- 按“名字+来源”列出工具：遮蔽池显示被隐藏/禁用的条目（含被遮蔽的**原生** `apply_patch`），
  启用列表显示当前可见条目（含插件自带的同名 `apply_patch`）。
- 只控工具可用性；不涉及 schema 编辑。

### 4.4 预览
- 预览 = 真实装配结果（该预设 + 工作区）；有活动会话用会话真实结果，无会话跑一次该预设装配。
- 只渲染系统提示词段；上下文中的 user-role 快照不计入系统提示词正文（但其中并入系统提示词的部分可控）。

### 4.5 三态与层级
- 段、工具、运行时上下文的显隐在 bootstrap/compaction/active 三阶段独立；
- “三态同步”开启时，三者改动均三阶段一起生效。
- 预设级 + 工作区级都可控；工作区级覆盖预设级。

## 5. 影响模块（预估）
- `vendor/prompt-customizer/index.js`：装配过滤（sections/contexts/tools）、inventory、preview 数据源改为真实装配；
  移除剩余目录池耦合；引入“名字+来源”身份。
- `src/kernel-skills.ts`：禁用技能的真实元数据还原（不被闸门桩替换）。
- `src/skill-toggles.ts`：闸门桩与真实元数据的关系（面板展示用真实源）。
- `src/client/prompt/*`（Panel / PreviewPane / PresetsPane / types）：段/工具/上下文清单与预览渲染、三态同步。
- `src/client/skills/*`（SkillsView / 卡片）：禁用技能卡片渲染真实元数据。

## 6. 待实现时核实的技术问题（事实，不属用户决策）
- host `system-prompt/assemble` 返回的 `sections` / `contexts` 是否携带 `source/provider/scope`，
  以及“并入系统提示词”的 contexts 的可识别方式。
- 工具注册表是否暴露 provider/source，用于“名字+来源”区分同名工具。
- 闸门 provider 桩条目如何在不影响模型可用性的前提下，为面板提供“真实技能元数据”。

## 7. 测试计划
- 单测：预设隔离（ptc 段不出现在一般预设清单/正文）；预览只含 sections（无工具 schema/签名）；
  同名不同源工具分别列出；禁用技能卡片还原真实元数据；上下文显隐与三态同步。
- 实机：切换 standard/ptc/minimal，核对预览=真实系统提示词；禁用技能卡片信息；同名工具遮蔽展示。

## 8. 分阶段落地
1. 预览/清单真实化 + 严格预设隔离 + 预览只 sections（修 ptc 串台、混入工具格式）。
2. 技能禁用卡片全量还原。
3. 身份“名字+来源”（工具先做，段同名后补）+ 同名工具分源展示。
4. 运行时上下文（并入系统提示词部分）显隐 + 三态同步涵盖。
