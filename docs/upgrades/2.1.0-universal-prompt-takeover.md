# 2.1.0 — 全域系统提示词接管

决策见 [ADR-0005](../adr/0005-universal-prompt-takeover.md)。版本 2.1.0，宿主契约不变（`engines.dsh: ^0.2.2-rc.1`）。

## 变更

1. **发现面**：`vendor/prompt-customizer/index.js` 新增 `collectLivePromptView` —— `buildPreview` 在「编辑目标 == 同预设活动 agent」时，复用同一份 `hint`（含草稿 patch、名义阶段）只覆盖 `scope` / `agent`，额外跑一次该 agent 自己 scope 的真实装配。一次 `promptCustomizerBase: true` 装配同时给出预过滤清单（`promptCustomizerBaseView`）与过滤后的正文（`sections`）。
2. **清单**：新增 `mergePromptEntries`，把「预设 base ∪ agent base」的 `sections` / `contexts` 按 `{name, source}` 去重（agent 视图优先、同名不同源分列）；`sectionOrderMap` 改取「预设链 ∪ agent 链」，否则 agent 段的规范 order 取不到会被排到尾部。
3. **预览**：有 live 视图时 `sections` / `text` / `contexts` / `emitted` / `takenOverBy` 都取自 agent 真实装配（过滤后），右栏显示模型此刻真正看到的系统提示词；无活动会话 / 装配抛错时 `warnOnce` 并退回纯预设装配。
4. **身份稳定化**：新增 `stableSourceOf`，把清单与预览里的 agent 来源统一收敛成 `{kind:'agent'}`（不带 session id）。`model.js:entryMatches` 已对 `agent ↔ agent` 按 kind 匹配（2.0.13），因此 UI 写入的屏蔽名单、草稿 `entryKey`、运行时候选三者身份一致且跨会话稳定。`buildSessionPreview` 也同步稳定化。
5. **隔离**：只用 `liveAgentForPreset(ctx, 编辑预设 id)`；`latestRootAgent` 仍只用于工具 catalog 与无会话兜底，切到别的预设不混入别会话的会话级段。
6. **工具侧不动**：`finalTools` / `buildToolUnion` / `catalogTools` 仍按纯预设装配计算，避免推翻 2.0.5–2.0.18 的工具目录回归约束。
7. 客户端零逻辑改动（`SectionsPane` 的「会话级」徽标、`phase-ops.ts:phaseRows` 已能渲染这些行）；只更新 `locales.ts` 的 `agentScopedHint` 文案。

## 动机（可观察的缺陷）

`dsh-hashline-edit@0.2.0` 在 `agent/created` 里用 `agent.ctx.systemPrompt.section()` 注册三段动态 `text` provider：`tool:read` / `tool:apply_patch` / `tool:undo_last_edit`。2.0.22 的 `/inventory` / `/preview` 只跑纯预设装配（live 段恒传空数组），导致：

- `tool:undo_last_edit` 在可编辑清单里根本不存在；另两段显示的是宿主同名段的原文；
- 即使勾了屏蔽，UI 写的 `{name, source:{kind:'global'|'preset'}}` 与运行时候选的 `{kind:'agent'}` 命不中（`entryMatches` 要求 `sourceKey` 相等），模型照样收到插件指引。

运行时过滤链（`applySectionPolicy` + `forceSections` 包装）本已支持 agent 来源，缺的只是「UI 发现 / 枚举」这一环。

## 行为变化（用户可见）

- 提示词页左栏新增带「会话级」徽标的行（插件在 agent 作用域注册的段），可独立屏蔽 / 替换 / 排序；同名不同源分两行。
- 右栏预览从「纯预设装配」变为「同预设活动 agent 的真实系统提示词」，与 `/session` 一致；无活动会话时保持原行为。
- 屏蔽一个会话级段后，最终系统提示词正文与 `/session.sections` 都不再含它；撤销即恢复。
- 工具页、三阶段名单、预设隔离、`/config/apply` 写盘格式、配置 schema 全部不变。

## 明确不纳入

- 工具 schema 的 `description` / 参数 JSON Schema：走 `GenerateOptions.tools`，不是系统提示词 token（宿主 "tool declarations remain provider-owned"）。本插件仍只做工具显隐，不做签名编辑。
- 不并入系统提示词的 user-role 消息、工具结果、LLM 请求体里另加的文本。
- 无活动会话时枚举 agent 作用域段：宿主 `systemPrompt.layers` 没有「列出所有作用域」的 API，属于契约边界。

## 验证与反例

- 反例：把 `buildPreview` 里 `liveBase.sections` 换回空数组，或让 `stableSourceOf` 返回带 session id 的原始 source，新增用例必须失败。
- 组合用例：会话级段进入 `/inventory` 且 `source.kind==='agent'` / `scope==='agent'`；同名不同源分两行；写入 `{kind:'agent'}` 屏蔽名单后 `/preview.text` 与 `/session.sections` 都不含该段、撤销恢复；换一个不同段名的插件段同样可枚举（非样例特判）；切到别的预设不串台；无活 agent 不抛错；工具目录行数 / 状态与变更前一致。
- `npm run check`（构建 + 全量单测 + 宿主 / 客户端 smoke）为交付门禁；`docs/testing/feature-matrix.md` 的 H 节 13/13 是 1.x 历史结果，不作为 2.1.0 的当前验证结论。
