# 2.1.3 — 全局 MCP 持久化修复

版本 2.1.3，基于旧 **v2.1.3** 代码继续修改；2.2.0 的“技能与 MCP 全三层虚拟化”未发布使用，本版丢弃该方向。宿主契约不变（`engines.dsh: ^0.2.2-rc.1`）。

## 缺陷：全局 MCP 添加后重启丢失

面板“添加 MCP Server（全局）”走 `POST /api/triad/mcp-config` 的 `action: add`。旧实现调用 root Include 树的 `tree.create()`：

- DSH 的 `runProfile()`（`apps/cli/src/profile-boot.ts`）与 `prepareProfile()` 在每次启动时都会把 profile 根 `cordis.yml` 重写为 `PROFILE_ROOT_CONFIG`（空数组）：注释明确是防止 Loader tree write-back 把组合行“烤”进根文件、导致下次启动重复插入。
- root Include 树没有对应 patch 的运行时新增行，最终由 `cordis-plugin-include` 的 journal 写进 `cordis.yml`；于是添加当下 status 可见，下一次启动被启动器清空。
- 真实复现（DSH 0.2.2-rc.1，临时 web profile）：添加 `zz-repro` 后 `cordis.yml` 出现该行、`cordis.patch.yml` 不变；重启后 `cordis.yml` 回到 `[]`，`GET /api/triad/mcp-status` 不再有 `zz-repro`。

预设级添加走 `configEditor.edit()`（写 profile 的 `cordis.patch.yml`），工作区级走项目根 `.mcp.json`，两者都不受该启动重写影响，所以用户感知是“有时丢、有时不丢”。

## 数据落点：三层全部磁盘

| 层 | 落盘位置 | 写入方式 |
|---|---|---|
| global | `$DSH_HOME/mcps/<serverName>/mcp.json` | 标准 `.mcp.json`；启停意图在同目录 `.dsh-prompt-customizer.json` |
| preset | profile `cordis.patch.yml` 的预设声明行 `config.plugins` | DSH `configEditor` 原子写 |
| workspace | 项目根 `.mcp.json` | 插件合并写 |

全局目录约定：

- 新增一台 Server 创建 `<serverName>/mcp.json`，内容为
  `{ "mcpServers": { "<serverName>": { "type": "...", "command": "...", "args": [] } } }`；
- 读取兼容旧 `mcps/**/mcp.json`，同名以 canonical `<name>/mcp.json` 优先；
- 手写在其他 `mcps/**/mcp.json` 里的配置可被列出与挂载，但面板不改写（`owned: false`，只读）；
- `${VAR}` 以原文本写进 JSON，挂载前才转成 Loader 的 `!!js` 模板，不把 `{ "__js": ... }` 内部标记写进用户文件。

## 运行时

- 启动成功后通过 `appReady.onReady()` 把全局行挂到 root Loader 内存树；`disabled` 行只保留在元数据里、不激活。
- 全局新增/启停/删除/编辑同步写 `.dsh/mcps` 与内存条目；HTTP 响应不等 mcp-client 的首次连接（避免 30s startupTimeout 拖住面板）。
- 旧版 runtime 行迁移：2.1.3 中间版本 SQLite 账本（`mcp/global-servers/<profile>`）首次读取时迁到 `.dsh/mcps` 并删除旧 doc；`cordis.yml` 里仍存活的 runtime 行沿用首次升级收养逻辑。

## 影响模块

- `src/mcp-global-store.ts`：SQLite 账本 → `.dsh/mcps` 文件账本（扫描、canonical 写、原子替换、启用状态元数据、迁移）。
- `src/mcp-status.ts`：新增/编辑落盘纯配置，挂载时再转 Loader 配置；启停/删除同步元数据与内存条目；状态把旧 mcps 文件行标为只读。
- 测试：`test/mcp-global-store.test.mjs` 重写为磁盘账本；`test/mcp-status.test.mjs` 适配。

## 验证

- 全量单测：**193/193 通过**；
- `npm run build`：成功；`npm run smoke`：宿主/客户端全绿；
- 真实 DSH web profile：添加 `zz-disk`（codegraph）后生成 `~/.dsh/mcps/zz-disk/mcp.json`，工具 `mcp__zz-disk__codegraph_explore` 注册；停止并重启后仍为 `toolCount=1`；`cordis.yml` 保持空模板；toggle 写 `.dsh-prompt-customizer.json`，remove 删除 canonical 文件。

## 已知边界

- 不监听 `mcps/**` 外部编辑；手改文件后需重启或重新打开面板读取状态。
- 旧非 canonical `mcps/**/mcp.json` 行在面板只读，避免误删用户手工文件。
